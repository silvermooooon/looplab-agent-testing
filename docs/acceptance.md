# 第一版本地验收

验收日期：2026-10-22。运行环境为 Node.js 24.19.0、PostgreSQL 18.6 Docker 服务、Google Chrome 与真实 GPT 6 Luna Responses API。被测产品为项目内独立的 `/demo` 登录/对话应用，浏览器操作和模型请求均真实执行。

## 已通过

| 范围       | 实际验收                                                                                                              |
| ---------- | --------------------------------------------------------------------------------------------------------------------- |
| 核心与协议 | 41 项离线行为测试：Agent loop、工具调用、参数校验、取消、订阅失败、Responses reasoning 回传、截断保护、模板和凭据处理 |
| 构建       | 服务端和前端严格 TypeScript 检查、Vite 生产构建                                                                       |
| 真实模型   | 固定 `gpt-6-luna`，完成 Responses 工具调用并将结果回填给模型                                                          |
| 用户与权限 | 创建 3 个独立账户；非成员读取项目被拒绝；只读成员可以查看、不能写入用例                                               |
| 生成与验证 | Agent 探索真实登录/对话页面，生成登录、发送消息、检查回复、截图 4 个节点；新浏览器回放通过                            |
| 团队共享   | 第二位用户读取相同 revision ID 并执行同一流程；执行没有 Agent 调用，也没有创建新节点版本                              |
| 去重       | 相同 spec 再次提交返回原 revision ID                                                                                  |
| 多环境     | 复制到预发布环境，重映射 revision ID 后回放通过                                                                       |
| 故障证据   | 手动创建带错误选择器的新版本，实际执行失败，保留失败截图                                                              |
| 局部修复   | GPT 6 Luna 修复目标节点并生成新版本；完整流程再次通过；预发布环境所有 revision ID 未变化                              |
| 脚本导出   | 导出 TS 脚本不含环境凭据；使用 Playwright 在独立命令进程实际执行，4 个节点全部通过                                    |
| 多实例     | 同时启动 2 个 Node 服务连接同一 PostgreSQL；4 个回放任务被不同 worker 领取并全部通过                                  |
| 取消       | 通过共享队列提交取消，任务最终进入 cancelled 状态                                                                     |
| 界面       | 浏览器登录、共享节点列表、流程副本编辑器、报告页面；1512px 桌面与 390px 移动布局无横向溢出；无浏览器 pageerror        |

完整端到端验收由 `scripts/acceptance.ts` 实现。真实运行的 ID、节点数量与验收时间保存在本机 `.data/acceptance-result.json`；屏幕截图位于 `.data/workspace.png`、`.data/run-report.png`、`.data/mobile.png`。本地账户及秘密配置不提交到 GitHub。

额外的独立验证脚本为 `scripts/verify-export.ts` 与 `scripts/verify-collaboration.ts`，它们使用端到端验收创建的项目继续验证，不重新生成测试组件。

## 未覆盖的场景

没有用户提供的生产目标地址，因此尚未验收其他业务站点、跨域 SSO、验证码/MFA 或长时间压力负载。进程崩溃后会通过租约过期标记失败，不提供浏览器状态续跑。截图被共享数据库持久化，但尚未进行大规模附件存储压测。
