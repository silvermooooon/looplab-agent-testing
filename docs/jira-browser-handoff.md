# Jira 浏览器集成交接

Jira 集成已具备可独立调用的需求读取、用例管理、流程保存、执行、结果回写和状态调整入口。业务操作由本地 Playwright 浏览器脚本完成，Agent 负责选择阶段、整理内容、检查脚本结果和修复页面定位规则。本文描述当前实现；真实内网 Jira 的适配和验收仍需场内完成。

## 运行位置与配置

LoopLab 服务、Agent 执行器和自动化浏览器运行在用户本地电脑上。用户在项目聊天中提供 Jira Ticket 链接即可开始；“Jira 需求”页面的阶段入口也会进入聊天，预填可编辑的请求，用户发送后执行。

- Jira 链接支持 `/browse/KEY-123` 或 `selectedIssue=KEY-123`。链接必须使用 HTTP/HTTPS，且不能内嵌账号密码。
- Jira 业务操作通过网页进行。没有 Jira REST API 调用，也不需要新增 Jira API Token、账号或密码环境变量。
- 被测应用继续使用所选项目环境的地址、变量和加密凭据。Jira 使用独立浏览器目标，切换站点时关闭旧浏览器，避免将应用凭据传给 Jira。
- 聊天请求记录本机 `executor_id`，只由同一主机、同一工作目录的执行器领取。共享 PostgreSQL 让团队复用需求、用例、节点和流程；Jira 浏览器与接管现场留在发起请求的本机。
- Jira 登录状态保存在 `.data/jira-sessions/<用户 ID>/<项目 ID>/<站点哈希>.json`，按用户、项目和站点隔离，文件权限为 `0600`。这些文件由 Git 忽略，不写入共享数据库。更换电脑或工作目录需要在新执行器重新登录。

## 独立阶段与实际工具

用户只要求某个阶段时，Agent 完成该阶段后结束本轮。中间产物持久化到项目，可由其他成员编辑，也可在新对话中继续。

| 阶段           | Agent 工具                                              | 输入与产物                                                                                                                       |
| -------------- | ------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------- |
| 查找、读取需求 | `list_jira_issues`、`jira_read_issue`                   | 输入 Ticket 链接，保存页面读取的标识、标题、描述、验收条件、评论、状态和采集时间；返回 `missingFields`，缺失字段不能当作完整需求 |
| 管理测试用例   | `list_test_cases`、`read_test_case`、`save_test_case`   | 创建或编辑项目用例，关联 `jiraIssueId`，保存版本历史；编辑须提供读取到的 `expectedVersion`                                       |
| 编排并保存     | `list_nodes`、`save_node`、`save_flow`                  | 根据选定用例的当前内容调查被测页面，复用节点版本，传入 `caseId` 与 `caseVersion`；保存流程，本阶段不自动重放                     |
| 执行流程       | `list_flows`、`run_flow`                                | 运行当前环境的已保存流程，在全新浏览器产生独立的子运行记录，返回真实状态、汇总和运行 ID；Agent 可继续检查或回写                  |
| 查找执行证据   | `list_project_runs`、`read_run`                         | 跨对话查找当前项目的运行，读取状态、汇总、错误、执行事件和截图等产物 ID                                                          |
| 回写结果       | `jira_publish_result`                                   | 输入项目内 `issueId` 和 `runId`，从持久化运行证据生成评论，通过 Jira 页面提交并回读核验                                          |
| 调整状态       | `jira_transition`                                       | 输入 `issueId` 与用户指定的目标 `status`，可选 `transitionLabel` 指定不同的菜单操作文字，执行后核验实际状态                      |
| 修复站点脚本   | `jira_inspect`、`jira_investigate`、`save_jira_adapter` | 脚本失败后查看真实页面，调查菜单或标签页，保存已确认的选择器并重试对应阶段                                                       |

`finish_flow` 保留原有“保存后结束 Agent 编排，再独立重放”的行为。需要在运行后继续回写 Jira 的对话使用 `save_flow → run_flow → jira_publish_result`。单纯生成用例不生成流程，单纯保存流程不表示测试通过，聊天状态“已回复”也不表示测试通过。

典型分阶段请求：

1. “读取这个 Jira 链接，只生成用例并保存到项目。”
2. 在用例页面手动编辑，查看版本历史。
3. 新开对话：“读取用例 ID 的最新版本，生成并保存流程，先不运行。”
4. “运行流程 ID，并检查结果。”
5. 新开对话：“将运行 ID 的结果回写到这个 Ticket。”
6. “将这个 Ticket 调整为待验收。”

## 用例版本与执行证据

`test_cases.version` 从 1 开始。内容或 Jira 关联变化时创建新版本；内容不变时不增加版本。历史记录包含标题、测试说明、当时关联的 Jira ID、修改人和时间。聊天草稿首次正式保存时也保留其原始版本。

保存流程时检查选定用例仍为调用方读取的版本，否则返回 `409`，要求先核对最新内容。新流程固定 `case_version` 和节点 revision ID；之后修改用例不会修改已有流程。界面显示流程依据的版本以及用例更新提醒。复制环境保留原流程的用例版本。迁移前的流程没有可靠版本依据，保留 `case_version = NULL`，显示为历史版本未知。

节点修复保留原流程的断言与无关节点。如果原流程的用例版本已过时或未知，拒绝直接修复并重新绑定当前版本；需要先核对当前用例再编排，避免旧断言被误记为验证了新需求。

独立执行使用流程固定的用例版本生成运行快照。回写检查该执行快照当时关联的 Jira Ticket，不使用后来改动的用例关联替代原证据。只有已经结束、事件写入完成且包含真实流程快照的 `passed`、`failed`、`cancelled` 运行可回写；普通聊天完成或仅保存流程的运行不能回写为测试结果。

项目 API：

- `POST /api/projects/:pid/cases`：创建用例。
- `PUT /api/projects/:pid/cases/:cid`：保存修改，界面与 Agent 传入 `expectedVersion`。
- `GET /api/projects/:pid/cases/:cid?version=N`：读取当前或指定历史版本。
- `GET /api/projects/:pid/cases/:cid/versions`：返回按版本倒序排列的历史数组。
- `POST /api/projects/:pid/flows`：支持 `expectedCaseVersion`，新流程固定保存时的用例版本。
- `GET /api/projects/:pid/jira`：返回项目需求快照、关联用例、站点脚本和回写记录。
- `PUT /api/projects/:pid/jira/sites`：保存指定 origin 的站点适配配置。

数据库迁移 v9 增加用例版本和流程版本依据；v10 增加 Jira 需求、站点脚本及历史、回写记录、本机执行器和父子运行关联。启动时自动迁移。

## 条件登录与同一现场接管

读取、发布评论和状态转换共用 `ensureTicket`。脚本先打开目标链接并核对页面 Ticket 标识；已经登录时直接执行。出现密码、验证码、已配置登录元素或登录跳转时，脚本调用现有 `pauseForHuman`，保留同一浏览器上下文，用户在实时画面中完成登录并点击继续。

用户交还控制后，脚本回到原 Ticket，再次检查登录、访问权限和 Ticket 标识。仍需登录时再次请求接管；权限错误、Ticket 不存在或标识不匹配时返回错误。人工等待暂停运行总计时，但已经发出的单个浏览器操作仍可能达到自己的超时。登录过期后的继续操作必须以页面回读结果为准。

Jira 的独立浏览器允许真实页面发起 HTTP/HTTPS 顶层登录跳转，包括新窗口；通常只需提供 Ticket 链接，跳到企业登录页后即可人工接管。脚本显式导航仍限定在 Jira 自己或已配置的 origin，读写前仍须核对原 Jira 站点与 Ticket 编号。跨域内嵌登录框需要在“Jira 需求 → 站点脚本”配置准确的 origin；这些可选配置会共享到项目。被测应用浏览器继续使用原有同源限制。本地已验证第二个 origin 的登录跳转与继续；真实企业 SSO、多因素认证及复杂窗口链仍需场内实测。

实时预览使用现有聊天和运行报告中的浏览器面板，显示 Jira 阶段及最近的点击操作。独立流程的子运行沿用父对话的预览和接管入口，结果有独立运行 ID。

## 脚本优先、失败修复与回写核验

Jira 的通用读取、评论、状态转换算法位于 `src/integrations/jira.ts`。站点差异通过受约束的 JSON 配置表达，包括标题、描述、验收条件、评论、登录、权限提示、状态菜单和按钮的选择器，以及允许的登录 origin。默认选择器覆盖部分常见结构，不能保证直接适用于所有 Jira 部署。

每次执行先调用已有脚本。选择器失效时，Agent 用 `jira_inspect` 获取当前页面和配置，通过 `jira_investigate` 点击、按键或等待调查控件，再用 `save_jira_adapter` 更新有关字段。保存产生站点脚本新版本，遗漏字段继续保留。不要把未调查的选择器当作已验证修复。

结果评论由平台根据实际运行生成，包括用例及其版本、流程、环境、完成时间、结果、汇总和失败步骤。评论带稳定标识 `[LoopLab run <运行 ID>]`。发布前先查看评论区是否已有该标识；提交后回读标识及评论正文。重复调用可返回 `alreadyPublished`，不会主动再提交同一运行的评论。评论面板的分页、折叠和加载方式仍必须由场内适配确认，标识检查仅覆盖脚本实际读取到的内容。

状态转换只选择页面当前提供的目标选项，完成后核对显示状态；已经处于目标状态时不再次转换。默认用目标状态文字匹配菜单。若内网 Jira 的“转换操作名”与“状态名”不同，传入可选的 `transitionLabel`，并继续用 `status` 核验最终状态。

Jira 写操作由专门脚本执行并读取结果，不放入测试流程的“调查后再重放”路径。成功核验后写入 `jira_publications`，聊天中可查看对应 Ticket 和运行记录。

## 场外临时模拟服务与验收

临时模拟 Jira 的源文件、数据、日志和截图放在 `.data/jira-fixture/`，只监听 `127.0.0.1`。仓库忽略整个 `.data/`；提交前检查 `git status` 和 `git check-ignore`，不把模拟服务作为产品或受 Git 管理的测试依赖。

模拟站点应提供 Ticket、登录页、描述、验收条件、评论和状态菜单。通过本平台的聊天、浏览器、人工接管及真实流程运行验收，不新增 UT。类型检查和构建仅验证代码可编译。当前具体执行记录见 [自举测试](self-testing.md)；未记录的验收项不能视为通过。

场内接力顺序：

1. 本机启动连接共享数据库的 LoopLab；选定项目和可用测试环境，提供真实 Ticket 链接。
2. 验证自动登录跳转与接管、继续后的 Ticket 核验、同用户后续对话复用登录；有跨域内嵌登录框时配置对应 origin。
3. 确认描述、验收条件和评论读取完整；缺失时修复站点配置，重新读取后再生成用例。
4. 验证生成用例、人工编辑、版本历史和跨对话编排。修改用例后检查原流程仍显示旧版本。
5. 单独运行已保存流程，检查独立子运行、真实断言和截图；另开对话回写该运行。
6. 在测试 Ticket 上验证评论回读、重复发布、登录过期恢复和状态转换，再验证用户明确请求的完整链路。

## 尚未验证或未提供的能力

- 场外无法验证真实内网 Jira 的 DOM、富文本编辑器、工作流、权限模型和 SSO。默认适配器只是起点。
- 尚无 Jira 附件上传专用工具；当前回写为文字结果，不自动把本地截图或测试文件上传到 Jira，也不承诺本机链接可被其他人访问。
- Jira 阶段脚本在 LoopLab 运行时调用，不支持作为现有“导出流程”的独立脚本导出。包含人工接管或监听的普通测试流程仍受原有导出限制。
- Jira 需求页面展示最近 100 条快照和回写记录；Agent 查找需求、用例和运行支持分页。大量历史需求的管理页筛选仍可继续改进。
- PostgreSQL 共享资产不等于共享浏览器登录，其他用户或其他机器需建立自己的登录状态。
