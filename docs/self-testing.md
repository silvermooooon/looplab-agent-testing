# LoopLab 自举测试

LoopLab 可以把另一个 LoopLab 实例作为被测网站：测试工作台中的 Agent 读取项目知识，通过浏览器登录目标实例，生成共享节点和流程，并在新浏览器中重放。目标地址、账号和密码分别配置在项目环境的地址和加密凭据中。

建议使用两个实例和两个 PostgreSQL 数据库，目标数据库只放测试数据。Agent 调查页面和流程回放都会真实操作目标；独立数据库能避免修改日常工作区。两个实例可以使用同一个 PostgreSQL 服务。工作台和目标在同一台机器时，环境地址可使用 `http://127.0.0.1:4312`；跨机器执行时，地址应是执行器实际能访问的目标地址。

## 执行验收

1. 启动工作台，例如默认的 `http://127.0.0.1:4310`。
2. 创建独立的 `looplab_selftest` 数据库，授予目标实例的数据库账号权限。启动第二个实例，并将 `PORT` 设为 `4312`、`DATABASE_URL` 设为此数据库。实例启动时自动创建和迁移自己的 `qa` schema。
3. 准备工作台账户的本地凭据文件，格式为 `{"owner":{"email":"…","password":"…"}}`；请放在 Git 忽略的目录中并限制文件权限。默认读取 `.data/acceptance-credentials.json`，也可以用 `SELF_TEST_OWNER_FILE` 指向其他文件。现有 `npm run test:acceptance` 的本地凭据文件可直接使用。
4. 在工作台项目目录运行：

```bash
npm run verify:self
```

成功生成并验证后，可以不调用模型，直接重放上一次成功保存的流程：

```bash
npm run verify:self -- --replay
```

验证真实 AI 对话前，先成功运行一次 `verify:self`，并保持两个实例和数据库运行，然后执行：

```bash
npm run verify:self-chat
```

以后可以使用已有节点和流程再次执行这两个用例：

```bash
npm run verify:self-chat -- --replay
```

重放不需要重新生成外层测试流程，但目标平台仍会为每次对话调用真实模型。每次运行从新会话开始，结果不会依赖之前的回复。

此命令在已有自举项目中创建两个用例：普通对话与刷新恢复、多轮对话上下文。外层 Agent 通过真实浏览器在目标实例的新会话中发送问题，检查助手气泡的正文和“已回复”状态，再刷新页面验证消息持久化。多轮用例的第二个问题不包含第一轮约定的代号，只有第二条助手回复包含该代号才算通过。每个用例生成后会独立重放一次，产生真实模型请求；两个用例必须复用至少一个节点版本。结果保存在 `.data/self-test-chat-result.json`。

可设置 `SELF_TEST_TARGET_URL` 改变目标地址。脚本在目标数据库注册随机测试账号并创建一个项目、环境和知识条目；在工作台创建独立的自举项目、环境、背景知识和聊天会话。账号密码只进入工作台环境的加密凭据，不写入测试用例或生成节点。

背景知识记录了本次验收中发现的两个页面特点：多个链接指向项目列表，对话页包含嵌套的 `main`。Agent 仍需要调查实际页面并选择唯一元素；页面结构变化时应重新核对这些说明。

任务要求 Agent 将登录、项目、环境、知识库、Agent 对话页面及截图拆成可复用节点。独立重放必须通过项目名称、环境名称、知识标题和聊天标题的实际浏览器断言；随后脚本再发起一次普通流程重放，并核对节点版本未变化。结果包含项目、会话、流程和运行 ID，保存在被 Git 忽略的 `.data/self-test-result.json`。截图和详细事件保存在平台的运行记录中。

如果生成的流程未通过，脚本会以失败退出，并输出工作台项目和运行 ID。可在项目的运行记录中查看失败步骤，再从共享节点的“Agent 修复”入口修复该节点并重放。脚本不会自动修复或隐藏失败；`--replay` 读取的是结果文件中上一次成功记录的流程。

每次运行会创建新的隔离测试账号和项目；如需反复使用，请保留目标数据库、实例和工作台环境。目标实例重启或地址变化后，应保证工作台环境中的目标地址仍可访问。两个实例的认证 cookie 同名，手动同时查看时请使用不同浏览器上下文，或者分别使用 `localhost` 和 `127.0.0.1`。

## 当前边界

- 该验收验证登录和现有资产的浏览，不覆盖通过被测 UI 创建项目或环境。探索阶段和重放阶段都会执行写操作，创建类测试需要分别准备数据或提供清理机制，避免重名和唯一约束冲突。
- 被测对话使用另一个实例及独立数据库的 worker，执行普通 AI 对话，不递归生成新的测试。单个实例的 worker 串行执行任务；如果外层任务等待同一实例中的内层任务结束，内层任务会一直排队。
- 这是本地功能验收，不是并发性能测试。生成节点受模型输出影响；脚本检查实际断言和节点拆分，不把模型文字回复视作测试通过。

## 本地验收记录

2026-11-01 使用独立目标实例和数据库完成了自举。Agent 将登录、项目、环境、知识库、对话页面和截图拆成 6 个节点。第一次重放发现登录节点的链接选择器匹配了三个元素；修复登录节点后，下一次重放发现对话页面的 `main` 选择器匹配了两个元素。分别从两个节点发起 Agent 修复后，6 个节点和 4 项页面断言通过；再次直接重放通过，引用的节点版本保持一致。

将这两项页面特点写入知识库后，又在新建项目中从头生成测试：6 个节点和 4 项断言一次通过，随后不调用模型的流程重放也通过。

该结果也说明当前实现仍需人工发起修复：Agent 初次生成的选择器可能不唯一，且一次修复后，后续步骤仍可能暴露其他问题。

AI 对话自举验收新增两个用例：基础问答及刷新恢复、多轮上下文及刷新恢复。两个用例分别完成生成后的浏览器验证和两次独立重放；断言检查助手气泡的回复与“已回复”状态，第二轮问题不包含待回忆的代号。目标实例中每个用例均产生了三个独立会话，共完成九次真实助手回复。两条流程复用了登录、进入对话、新建会话、刷新和截图五个节点版本。
