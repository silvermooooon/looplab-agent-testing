# 管理 UI 与性能审阅（2026-10-22）

## 上游调研与实际复用

调研了 [Ant Design Pro](https://github.com/ant-design/ant-design-pro)、[shadcn-admin](https://github.com/satnaing/shadcn-admin) 和 [Refine](https://github.com/refinedev/refine)。本项目已有 Vite、React 和 Fastify API，最终采用 Ant Design 组件与 TanStack Query，不引入 Umi 或第二套 CRUD 数据框架。

- 阅读 Ant Design Pro 的 [table-list 页面](https://github.com/ant-design/ant-design-pro/blob/52506486ea134486937043c5fb677d89bbcd07f2/src/pages/table-list/index.tsx)，基准提交 `52506486ea134486937043c5fb677d89bbcd07f2`。采用其列表工具栏、行操作、表单弹窗、详情抽屉和写入后失效缓存的组织方式。未整包复制模板或移植 Umi。
- **直接依赖并使用** [Ant Design](https://github.com/ant-design/ant-design) 6.6.7 的 Layout、Menu、Table、Form、Form.List、Modal、Drawer、Select、Image、Alert 等；对话框焦点、键盘关闭、表单校验、分页和确认交互由组件库实现。
- **直接依赖并使用** [TanStack Query](https://github.com/TanStack/query) 5.104.5：缓存、请求去重、AbortSignal 取消、写入失效、按运行状态刷新、后台停止轮询。
- **直接依赖并使用** [React Router](https://github.com/remix-run/react-router) 7.18.4：项目、页面、环境、搜索、分页与报告可链接、可刷新、可前进后退。
- 以上项目为 MIT 许可；使用包管理器锁定依赖，保留各包自带许可。没有把自写控件包装成“复用模板”。应用特有的项目/环境权限、资产版本和 Agent 工作流仍由本项目实现。

## 原有问题与处理

| 原有问题                                 | 本次处理                                                                                                      |
| ---------------------------------------- | ------------------------------------------------------------------------------------------------------------- |
| 只有侧栏小按钮创建项目，没有项目管理首页 | 项目目录，搜索、分页、创建、编辑、归档、恢复、进入项目                                                        |
| 环境管理分散在小图标，配置要求手填 JSON  | 独立环境管理页，创建、修改、复制、切换、归档和恢复；变量/凭据键值表单                                         |
| 所有项目内容每 4 秒整包获取              | 元数据与资源列表拆分；每次只取当前资源页，默认 20 条，上限 100 条                                             |
| 已完成报告仍每 1.6 秒获取完整日志/快照   | 每批 250 条事件，游标增量合并；结束后停止轮询，表格只渲染当前 20 条                                           |
| 刷新丢失位置，无法分享具体页面           | React Router 路由与 URL 查询参数                                                                              |
| 手写弹窗缺少统一键盘/焦点处理            | Ant Design Modal/Form/Drawer；确认、错误、加载、只读状态统一                                                  |
| 2000 行单体组件与大量全局样式            | 拆分项目页、资源页、编辑器、报告、数据层，按路由/编辑器懒加载                                                 |
| 未压缩的静态脚本、外部字体依赖           | 构建生成 Brotli/gzip；复用 Fastify Static 的 preCompressed；哈希资源长期缓存，HTML 必须重新验证；移除外部字体 |

## 生命周期与共享数据

- 项目仅所有者可编辑、归档、恢复；环境由所有者或编辑者管理。
- 归档保留所有版本、流程、报告，阻止新的执行或资产写入；有排队/运行任务时拒绝归档。执行入队与项目/环境归档使用行锁串行检查。
- 凭据不回传明文。更新环境时在同一事务中合并指定新值、删除明确勾选的键，留空保留已有凭据。复制环境默认不复制凭据。
- 当前 UI 普通资源没有后台定时刷新；共享数据在重新进入、窗口回到前台（缓存过期后）或手动刷新时更新。不是实时协作推送。
- 为兼容旧验收脚本，保留 `/api/projects/:id` 聚合接口；新 UI 不使用此接口。

## 本地验收与测量

`npm run verify:management` 在启用 `/demo` 的本地服务上创建独立测试账户/项目，完成后归档测试项目，不调用 LLM。

共 11 组验收，覆盖：浏览器登录、创建/编辑项目、URL 校验、环境键值配置、凭据保留、复制隔离、刷新恢复、分页搜索、权限与归档恢复、真实浏览器脚本重放、超过 250 条事件的完整游标读取、截图与终态停止轮询、Brotli/缓存响应头、节点版本与固定历史版本的流程副本、1512px 与 390px 布局。

2026-10-22 验收项目包含 **45 个用例、25 篇长知识文档、2 个环境**。用相同项目比较 JSON 序列化后的未压缩响应体：

| 指标                              | 原实现                 | 新实现                         |
| --------------------------------- | ---------------------- | ------------------------------ |
| 进入用例页需要的数据              | 整个项目 554,173 bytes | 元数据 + 20 个用例 4,405 bytes |
| 空闲页面 8.5 秒内的周期请求       | 每 4 秒请求            | 实测 0 次                      |
| 已完成报告稳定后 4.5 秒的周期请求 | 每 1.6 秒请求          | 实测 0 次                      |
| 列表 DOM 行数                     | 全量                   | 每页 20 条                     |

该夹具下响应体减少约 **99.2%**，不代表所有项目都达到同样比例，也不是并发吞吐或生产负载测试。

## 仍需知悉的边界

- 成熟组件库增加首屏脚本体积。当前 App chunk 约 667 KB 原始 / 221 KB gzip，另有 React 入口及按需页面；构建仍提示大 chunk。已经懒加载页面、编辑器并预压缩，不声称 JS 包体比旧手写界面更小。
- 长事件历史按 250 条逐步获取，并只分页渲染；浏览器最终仍缓存完整报告，极长会话后续可改为纯服务端分页。
- 项目/环境采用可恢复归档，不提供破坏性硬删除。节点步骤的高级编辑仍为 JSON，流程组合和环境配置已使用表单。
- 列表按时间排序，搜索使用 PostgreSQL ILIKE；没有在此版本实现百万级全文检索、虚拟表格或多人实时推送。
